# Native1 phone capture: pair and save-route audit

## Finding

For the reported one-frame RAW16 capture, the source preserves the Camera2-delivered unsigned 16-bit sample buffer in the saved, uncompressed DNG before normalizing the buffer or running Photon's photographic renderer. The saved DNG is a Photon-authored container with Camera2-derived and potentially configurable metadata; it is not an untouched vendor DNG. No comparison against the original in-memory Camera2 buffer is available, so byte identity to that buffer is supported by the executed-route evidence and source, not directly measured from two buffers.

This audit inspected the uploads read-only. No file metadata or pixels were rewritten. It does not establish the camera HAL's processing before delivery, a complete sensor calibration, or any Hasselblad HNCS rendering. Native1's recovered Hasselblad primitive remains confined to its explicit diagnostic screen.

## Metadata transformations

`processing/render/Parameters.java` fills its structure from CameraCharacteristics and CaptureResult. `FillConstParameters()` (137–237) also invokes the tunable and sensor configuration injectors. `FillDynamicParameters()` (273–401) fills ISO, exposure, black/white levels, lens shading, focal length and aperture; configured black/white-level overrides and dynamic-level options can select different metadata values. `ReCalcColor()` (406 onward) obtains the neutral point and colour/calibration/forward matrices, with sensor-specific CCT configuration capable of replacing the selected matrices.

`processing/DngCreator.java::setParameters()` (464–519) writes these values to a new DNG. It constructs brand/model/software strings, generates wall-clock DateTime, casts black levels, converts float matrices to doubles, and writes a noise model and white-balance neutral point. Thus its metadata reflects Photon's selected parameter structure, rather than a byte-for-byte vendor metadata block.

`dngCreator.cpp::setGainMap()` (512–547) writes four DNG GainMap opcodes from the supplied row-major R/G/G/B grid. This is descriptive lens-shading metadata; it is not applied to the single-frame sample buffer before DNG save. A RAW developer may apply it later. The native writer also generates ActiveArea from the supplied buffer dimensions.

The isolated Native1 storage/configuration policy prevents automatic use of another Photon or Leica installation's external tuning directory, but that isolation alone does not turn the exported metadata into independently measured sensor calibration. The source cannot establish which runtime optional parameters were selected beyond the values actually embedded in the sample.

## JPEG dimensions and pairing limit

`processing/opengl/postpipeline/PostPipeline.java::Run()` (331–387) starts with the RAW size and allocates a bitmap at the rotated output size. `getRotatedCoords()` (150–160) swaps width/height for 90/270 degrees. For this full 4096 × 3072 capture and its portrait orientation, the ordinary path therefore allocates **3072 × 4096**, without a half-size step. The crop-reconstruction branch targets the full RAW size; energy saving changes tile size, not output dimensions.

`processing/processor/ProcessorBase.java::overlay()` (48–71) preserves bitmap dimensions. `processing/encoder/StillEncoder.java::encodeJpeg()` (184–205) passes that bitmap to `ImageSaver.Util.saveBitmapAsJPG()` (126–144). That function compresses the same bitmap and normally writes EXIF including its dimensions. No half-size resize exists in this save route.

The received JPEG's 1536 × 2048 dimensions and absent EXIF are compatible with a later resized/re-encoded copy, but the available evidence cannot locate that operation or prove that the file is the untouched on-device original. This does not block the DNG/raw-path audit and is not, by itself, evidence of an app output-size defect.

## Concrete export defects and repair scope

1. **WhiteLevel type:** The sample stores tag 50717 as TIFF RATIONAL. Adobe DNG 1.7.1 defines WhiteLevel as SHORT or LONG (specification p.29, independently checked in the main task). Both `DngCreator::createDng()` WhiteLevel calls currently select the writer's rational API. Native1A will select the existing unsigned LONG writer API and retain the exact integral numerical value. This is a metadata-conformance defect; it is not evidence that RAW samples are damaged or that a particular uploader failure was caused by the tag.
2. **Software provenance:** `processing/DngCreator.java` imports `de.hdodenhof.circleimageview.BuildConfig` at line 14, then formats that unrelated library's version at line 470. Native1A will use the app BuildConfig and an unambiguous standalone app/version string. The correct Native1 version remains available in this sample's ImageDescription.

No change to demosaic, colour, tone, Hasselblad primitive, RAW sample processing, capture policy or storage policy is needed for these two defects. The original uploads and Native1 APK remain unchanged.
